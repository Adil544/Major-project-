## Abstract
Customer churn is one of the largest hidden costs for subscription businesses; acquiring a new customer costs several times more than retaining an existing one. This project builds an end-to-end machine learning system that predicts whether a telecom customer will churn. The pipeline covers data cleaning, exploratory analysis, feature engineering, comparison of three classifiers with 5-fold cross-validation, hyper-parameter tuning, threshold selection, and deployment as a Streamlit web application. The final tuned Logistic Regression model reaches a ROC-AUC of 0.844 and recalls 81.8% of churners on unseen data, and the app converts predictions into concrete retention actions.

## 1. Introduction
Telecom operators lose a meaningful share of customers every year. A model that ranks customers by churn risk lets the retention team spend discounts and calls where they matter most, instead of spreading them across everyone.

## 2. Problem Statement and Objectives
**Problem:** Given a customer's account, service and billing details, predict whether they will churn.
**Objectives**
1. Understand the factors that drive churn through exploratory data analysis.
2. Build and compare classification models using a leak-free pipeline.
3. Optimise for catching churners (recall) while keeping precision usable.
4. Deploy the model as an interactive app that suggests retention actions.

## 3. Dataset
- 7,043 customers, 20 input features plus the `Churn` label; 25.7% of customers churned (class imbalance of about 1:3).
- Feature groups: demographics (gender, senior citizen, partner, dependents), account (tenure, contract, payment method, paperless billing), services (phone, internet, add-ons), charges (monthly, total).
- Data note: the dataset follows the structure of the public IBM/Kaggle *Telco Customer Churn* data. The bundled file is generated by `src/generate_data.py` so the project runs offline; replace it with the Kaggle file for the final submission.

## 4. Methodology
| Stage | What was done |
|---|---|
| Cleaning | Converted `TotalCharges` from text to numeric; 11 blank values imputed as monthly charge x tenure; removed duplicates and the ID column |
| EDA | Target balance, churn rate by category, KDE plots of numeric features, correlation heat-map |
| Feature engineering | `tenure_group`, `num_addons` (count of subscribed add-ons), `avg_monthly_spend` |
| Preprocessing | `ColumnTransformer`: StandardScaler for numeric, OneHotEncoder for categorical, inside a `Pipeline` so nothing leaks from test to train |
| Split | 80/20 stratified split (5,634 train / 1,409 test) |
| Model comparison | Logistic Regression, Random Forest, Gradient Boosting, 5-fold stratified CV on ROC-AUC |
| Tuning | `RandomizedSearchCV` (12 iterations) on the best candidate |
| Threshold | Chosen on out-of-fold training predictions to maximise F1 (0.51), so the test set stays untouched |
| Evaluation | Accuracy, precision, recall, F1, ROC-AUC, confusion matrix, ROC curve, permutation importance |
| Deployment | Streamlit app loads the saved pipeline and returns probability, risk label and suggested actions |

## 5. Exploratory Findings
- **Contract is the strongest signal:** churn is 40.9% on month-to-month, 11.8% on one-year and 3.0% on two-year contracts.
- **Tenure:** customers in their first year churn at 45.7%, falling to 4.9% beyond four years.
- **Internet service:** fibre-optic customers churn at 36.2% versus 19.7% for DSL.
- **Payment method:** electronic-check users churn at 30.8% versus about 22-24% for the other methods.
- **Support:** customers without tech support churn at 30.8% versus 26.5% with it.

## 6. Results
**5-fold cross-validation (ROC-AUC, training set)**
| Model | Mean | Std |
|---|---|---|
| Logistic Regression | 0.8219 | 0.0085 |
| Random Forest | 0.8094 | 0.0089 |
| Gradient Boosting | 0.8129 | 0.0073 |

**Final model: tuned Logistic Regression (C = 0.09), test set**
| Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|
| 0.740 | 0.496 | 0.818 | 0.617 | 0.844 |

Interpretation: the model catches about 82% of customers who actually leave. About half of the customers it flags do leave, which is acceptable because a retention offer sent to a loyal customer costs far less than losing a churner. Top drivers by permutation importance: Contract, tenure, average monthly spend, internet service, payment method.

Honest note: Logistic Regression beat the tree ensembles here. With roughly 7,000 rows and mostly linear effects, a simple, interpretable model is a legitimate winner and easier to explain to a business audience.

## 7. Deployment
`app.py` (Streamlit) collects a customer profile, rebuilds the same engineered features, scores it with the saved pipeline, and shows the churn probability, a risk label and rule-based retention suggestions (contract upgrade offer, tech-support trial, auto-pay incentive, onboarding call).

## 8. Business Recommendations
1. Offer incentives to move month-to-month customers onto longer contracts.
2. Run an onboarding programme in the first 12 months, when risk is highest.
3. Bundle online security and tech support for fibre customers.
4. Encourage automatic payment instead of electronic cheques.

## 9. Limitations and Future Scope
- Static snapshot data; no usage, complaint or call-centre logs.
- Predictions show association, not causation; retention offers should be A/B tested.
- Future work: SHAP explanations, XGBoost/LightGBM, survival analysis (time-to-churn), cost-sensitive threshold using customer lifetime value, a monitoring job for data drift, containerisation with Docker and cloud deployment.

## 10. Conclusion
The project delivers a reproducible pipeline from raw data to a deployed decision-support app, identifies the main churn drivers, and achieves an ROC-AUC of 0.844 with 82% recall on unseen customers.

## Appendix: likely viva questions
- **Why ROC-AUC and recall instead of accuracy?** The classes are imbalanced (26% churn); a model predicting "nobody churns" gets 74% accuracy but is useless.
- **How did you avoid data leakage?** All preprocessing sits inside the Pipeline and is fit on training folds only; the threshold was chosen from out-of-fold predictions.
- **Why did Logistic Regression win?** The signal is mostly additive and the dataset is small; complex models add variance without gain.
- **What would you do with the predictions?** Rank customers by probability and target the top slice with retention offers.
- **How would you improve it?** More behavioural features, SHAP, cost-based threshold, drift monitoring.
